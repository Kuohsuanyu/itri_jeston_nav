## 3. 校準 base_link(★ 這一步要先做,順序不能反)

**為什麼一定要排在外參前面**:`calib_extrinsic.py` 解的是
`base_link → camera_link`。base_link 本身還沒定好就去校外參,等於用一把
會動的尺去量東西 —— 量出來的數字沒有意義,而且第 5 步的疊圖會「看起來有點準
但就是差一點」,很難判斷是誰的問題。

### 3a. 把車停好

- 停在**平的地面**上,不要在斜坡、不要壓門檻、不要一邊輪子在地毯上
- 周圍地面看得到,不要四周都被箱子圍住
- 量測 30 秒內整台不要動,人也不要靠著

### 3b. 量

```powershell
J "cd ~ && source /opt/ros/humble/setup.bash && source ~/ws_livox/install/setup.bash && export ROS_DOMAIN_ID=0 && python3 calib_base_link.py"
```

**通過條件**(這支程式用三個獨立來源互相驗證)

| 區塊 | 通過條件 | 不過代表什麼 |
|---|---|---|
| A. IMU | 相對抖動 < 0.02 | 量測時車有動,重來 |
| B. 地面擬合 | 跟 IMU 的重力方向差 < 2° | 地不平,或擬合到桌面/坡道 |
| C. 交叉檢查 | 新座標系裡相機 pitch < 3° | 相機不是真的平視,或外參本來就有誤 |
| D. odom | 明確印出斜幾度 | 這裡會告訴你二維地圖的尺度誤差有多少 |

三個都過,結果才可信。B 段還會給你**光達離地高度** —— base_link 的原點要放在
地面上,這個值沒有就放不準。

### 3c. 套用

把程式印出的那 12 行(`BL_*` 和 `OD_*`)貼進 `~/slam2d/base_link_tf.sh`
的「改這裡」區,覆蓋掉原本的 identity。

```powershell
J "nano ~/slam2d/base_link_tf.sh"     # 或用 pscp 傳改好的檔案上去
J "bash ~/slam2d/base_link_tf.sh"
```

**通過條件**
- `重力在 base_link 裡` 的 z 分量接近 1,`離垂直 x.xx 度` 顯示 **OK**(< 1.5°)
- `odom -> base_link` 的 **z 接近 0**(base_link 在地面上)

### 3d. 重跑二維建圖

高度帶的基準跟著變了,必須一起換。腳本會自己偵測 `BL_PITCH` 是不是還是 0,
自動切成相對地面的 `0.10 ~ 1.50`。

```powershell
J "bash ~/slam2d/start_slam2d.sh"
```

**通過條件**:開頭印 `base_link 已校準,/scan 高度帶相對地面`,
且 `/scan` 有頻率、`/map` 有 info。

## 4. 重新校準相機外參

base_link 動過了,舊的外參值(2026-08-07 那組)已經失效 —— 它是相對舊的
傾斜 base_link 算的。

擺位要求:對著**有牆角 + 地面 + 幾個箱子/椅子**的地方,物體距離 1~3 公尺。
**不能對著單一平牆** —— 那是退化情況,沿牆面滑動都符合,ICP 會給你一個
殘差很小但完全錯誤的解。

```powershell
J "cd ~ && source /opt/ros/humble/setup.bash && source ~/ws_livox/install/setup.bash && export ROS_DOMAIN_ID=0 && python3 calib_extrinsic.py"
```

**通過條件**
- 開頭印 `相對 base_link 傾斜 ~30 度`(如果印 0 度,代表第 3 步沒生效,回去看)
- 校準後 RMS **< 0.04 m**
- 新的 pitch 應該接近 **0**(base_link 水平了,平視的相機自然就是 0)

把印出來的六行填進 `~/slam2d/camera_extrinsic.sh`,然後:

```powershell
J "bash ~/slam2d/camera_extrinsic.sh"
```

```powershell

```

瀏覽器開 **http://192.168.40.98:8094/**

畫面是**相機影像 + 光達點投影疊在上面**,顏色代表距離(藍近紅遠)。

### 怎麼判斷「完全一致無偏差」

不要看整體感覺,要看**邊緣**。找畫面裡 2~4 公尺處有明顯直線邊緣的東西:

- 桌子的邊
- 門框、窗框
- 椅腳、桌腳
- 牆與牆的交線、牆與地板的交線

外參正確時,**光達點的邊界會精準壓在影像的邊界上**。點跨過桌緣落到地板上、
或是離桌緣還有一段空白,就是有偏差。

按 **「影像邊緣」** 模式最好判斷:影像被轉成白色線條,光達點是彩色的,
兩者該不該重合一眼就看得出來,不會被材質顏色干擾。

| 看到的現象 | 意思 | 調哪個 |
|---|---|---|
| 點整體往上/下偏 | pitch 或 Z 差 | 先試 pitch,遠處偏移比近處大就是 pitch |
| 點整體往左/右偏 | yaw 或 Y 差 | 同上,遠近偏移量一樣就是 Y |
| 近處對齊、遠處散開 | 角度誤差(roll/pitch/yaw) | 角度 |
| 遠近偏移量一致 | 平移誤差(X/Y/Z) | 平移 |
| 點沿著畫面旋轉 | roll | roll |

右側滑桿可以**即時微調**,畫面同步更新。調到滿意就按「複製設定」,
貼回 `~/slam2d/camera_extrinsic.sh` 再跑一次那支腳本。

> 滑桿的數值**就是**檔案裡的值,不需要任何換算 —— 疊圖用的變換是直接從
> 滑桿建出來的,不是從 TF 讀的。

**通過條件**:2~4 公尺處的物體邊緣,光達點與影像邊緣的偏差目視 **< 2~3 個像素**。

## 順序為什麼是這樣

```
清 nvblox ──> 起服務 ──> base_link ──> 相機外參 ──> 疊圖驗證 ──> 彩色點雲
                            │              │
                            │              └─ 基準是 base_link
                            └─ 決定了「水平」和「地面」在哪裡
```

`base_link` 是所有東西的基準。它沒定好,外參是錯的、二維地圖有 13% 尺度誤差、
`/scan` 的切片是斜的、Nav2 的 costmap 也跟著歪。先把尺定好再量東西。
